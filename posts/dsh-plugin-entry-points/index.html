DSH 插件实践：把会话入口延伸到手机、微信与远程 SSH

2026-11-12 · 5 分钟 · 2135 字 · Attack825

凌晨一点多，我躺在床上，手机屏幕是房间里唯一的光。电脑在桌上亮着，今晚的几次操作都是它自己跑完的。

先是一个念头：让电脑静音。歌还在放，我懒得起身。接着是第二个念头：明天下午一点半，提醒我给女朋友发消息。

这两件事我都没有起身，也没有碰电脑。第一件在微信里说了一句，第二件排进定时任务，到点在微信里叫我。

真正让这件事成立的，是我在 DSH 上装的一组第三方插件。它们把同一个 agent 接进了不同的地方：手机上、微信里、远程服务器上。这篇文章按用法把它们分成三组讲：入口、观测、节奏。

插件解决的是距离#

模型每个版本强一点，这个速度你控制不了。你能控制的是另一件事：需要它干活的时候，它在不在你手边。

过去一年我放弃过不少顺手的想法，原因都很无聊。要开电脑，要连远程，要坐在桌前等它跑完。念头和维护成本一比，就算了。

这些插件做的就是压缩这段距离。入口让我在任何地方找到它，观测让我敢把长任务交出去，节奏让它主动来找我。

先说入口。它决定了我从哪里进入同一个会话。

入口：手机、微信、服务器#

DSH Bridge 更接近换一道门。它给 DSH 开了一条远程通道：局域网里生成二维码，手机扫一下就能接着用。人不在同一个网络，就换成 Cloudflare 隧道或者自建隧道。它还附带微信、QQ、飞书、Telegram 的机器人入口。

关键在于接着用。手机和电脑上是同一个会话、同一份上下文。手机上能继续派活、看进度、改主意，回到电脑上还能在原来的位置继续。

它也有明显的短板。手机屏幕读长日志很难受，隧道偶尔有延迟，信号差的时候体验会明显下降。

dsh-wechat 解决的是更小的摩擦。它把 DSH 变成微信里的一个机器人，你说一句，它做一件，回一句。

晚上让电脑静音就是这么办的。我发“把电脑静音”，它执行完回一句好了。整个过程不用解锁电脑，也不用打开任何应用，微信本来就在我手上。

第二个例子更能说明它的价值。我第二天下午要提醒女朋友一件事，于是让它建了一个定时任务，设在 13:30，到点通过微信推给我。提醒落在了一个我本来就会看的地方，而不是一个需要我主动打开的清单。

微信的代价同样明显：它适合短指令，不适合长需求。要改一份文档、调一段代码，最后还是得回到主界面。

DSH Remote-SSH 处理的是第三种距离。它把 VSCode Remote-SSH 那套体验搬进了 DSH：连上服务器或者超算，有远程工作区、文件树、终端。

以前跑一次实验要走一整套流程：打开笔记本，连 VPN，开终端，改两行，提交，盯着日志。现在我可以躺在床上，用手机或者平板改完那两行，提交，然后看日志滚动。实验在机房跑，我在被窝里等结果。

有一点不太浪漫，但必须说：SSH 那台机器该有的纪律一样没少。长任务要能脱离终端活着，日志要落盘。手机一锁屏、连接一断，你只能重跑。

入口装多了，副作用也跟着来。同一件事可以从四个地方发起，通知也散在四个地方。我的做法是先定一个主入口，电脑。手机和微信只用来接收和派活，读长内容一律回到电脑。这样不容易把同一个任务在两处各开一个会话。

还有一件事要提前想清楚。把 agent 接到公网和微信上，等于把指挥权也扩了出去：谁能给这个机器人发消息，谁就能让它在你电脑上执行命令。我的处理是把隧道视作临时通道，用完就关；微信机器人只留给自己；删除文件、推送代码这类动作，仍然保留人工确认。

观测：看得见才敢放手#

放手的前提是能看见。这几个插件不产出结果，但决定了我敢不敢把任务交出去。

dsh-context 给了一个上下文面板，能看清一轮对话里 token 花在哪里、上下文是怎么一点点长起来的。它帮我做两个决定：什么时候该收一收，什么时候该开一个新会话。

dsh-trace-synopsis 是我写的，它把一整场会话的 trace 压成一页摘要：目标是什么，经历了哪几个阶段，动了哪些文件，跑了哪些命令，错在哪里。跑完长任务先看这一页，再决定要不要翻细节。

dsh-workspace-view 也是我写的，它是一个工作区总览：跨工作区的最近活动、自己分好的颜色分组、一键回到某个会话。同时开着三四个项目的时候，它省掉的是我刚才那件事在哪个窗口里的反复搜索。

dsh-bottom-info-bar 最小，只在输入框下面显示当前模型、余额和花费。装上就忘，卸载就难受。它把这次会花多少钱从猜测变成了随时能扫一眼的数字。

它们加起来没有让 agent 多干一件事。但它们让我布置任务时心里有底。

节奏与协作：它什么时候来找你#

另外两个插件管的是节奏。

dsh-plugin-notify-sounds 需要我做决定、或者任务跑完时响一声，点系统通知可以直接跳回窗口。它还支持静音时段和重复提醒。凌晨的提示音不该把我吵醒，早上该叫的时候又要叫得醒，这个开关看起来小，用起来差别很大。

DS-Bot 走的是另一个方向：它把单个助手扩成一组长期驻留的 Bot，有主 Bot，有 Bot 之间的消息，有群聊。我还没把它用到很复杂的程度，但已经能看出它的位置。有些活儿不适合塞进一个临时会话里，它们需要一个固定的角色长期接着。

回头看这些插件，它们没有让 DSH 更聪明。它们做的是同一件事：把你得坐在电脑前这个前提，一点点拆掉。

入口从电脑换到手机和微信，工作对象从本地换到远程服务器，过程从黑箱换到可观测，提醒从我记得换到它来找我。四件事叠起来，才有资格说躺着把活干了。

我判断一个生态强不强，不看插件数量。我看这些插件是不是长在同一个东西上。上面这些，指向的都是同一个正在干活的 agent、同一份会话、同一套上下文。换个入口，活还在原地接着干，这才是我觉得厉害的地方。

这篇稿子也是这么出来的：我在床上交代一句，它写完，我审一遍，它再推送发布。
